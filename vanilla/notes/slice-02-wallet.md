Crypto rationale (why this shape): classic derivation is FOR COMPAT (legacy
brainkeys must reproduce #1/#2 keys bit-for-bit — proven in §3); PBKDF2-600k +
AES-GCM is FOR STORAGE (matches #3's audited keystore properties, platform
WebCrypto, no vendored code needed); vendored noble is FOR SECRET-SCALAR OPS
ONLY (private→public; base58/ripemd160 checksums are ported pure-JS from #3
`crypto-utils.js` because WebCrypto has no ripemd160 — credited in the
`crypto.js:9-22` header).

Fresh-wallet seq convention (vanilla convention, NOT chain consensus):
owner←seq0, active←seq1, memo←seq2 (`wallet.js:171-190`). Import look-ahead
seq0..9 rediscovers regardless of which seq the registrar used.

Deviation (generation only, derivation unaffected): `suggestBrainkey` uses
`Math.floor(49744*num/65536)` where #2 used `Math.round`
(`astro-ui/src/bts/ecc/key.js:154`). Round can overflow the 49,744-word list
at the top edge; floor is uniform on [0, 49743]. Recorded in the
`crypto.js:17-19` header. `normalizeBrainkey` preserves case (no uppercasing —
that was #3's SLIP-48 path, which must never enter `vanilla/`; SLIP grep §6
is CLEAN).
