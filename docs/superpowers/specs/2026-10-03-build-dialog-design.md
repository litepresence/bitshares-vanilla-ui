# Build-dialog archive in /about — design

Date: 2026-10-03. Status: approved sections 1–3, awaiting spec review.
Source history: `docs/vanilla-ui-prompts.md` (413 prompts) +
`docs/vanilla-ui-dialog.md` (413 exchanges), generated by
`tooling/collate_vanilla_prompts.py` from opencode.db.

## Goal

House the original build-story chat — every user prompt that created this
wallet, with the assistant's replies, ending after issue #1 was addressed
(dialog #413) — inside the wallet's `/about` page as a historical artifact.

## Decisions (from brainstorming)

- Purpose: both, layered — short origin story up front, full dialog behind it.
- Full 413-exchange dialog ships fully embedded in `vanilla/` (~500KB accepted).
- Home: `/about` section, no new route.

## 1. Data file

- Path: `vanilla/assets/build-dialog.js`. A `.js` data file (not `.json`)
  so it loads via injected `<script>`, which works on both `file://` and
  `http://` (`fetch()` of JSON fails on `file://` in Chrome — plug-and-play
  rule). Lazily injected on first expansion only; guarded re-inject.
- Shape: `window.BuildDialog = [{ n, time, session, user, reply }, ...]`,
  numbering identical to the docs (`#N`). `reply: null` where no reply was
  recorded (rapid-fire bursts; the reply attaches to the last prompt).
- Strings serialized with `JSON.stringify` semantics. Short keys documented
  in the file header.
- Provenance header comment: what it is, generated-when, generated-by
  (`tooling/collate_vanilla_prompts.py`), 413 exchanges / 14 sessions, the 6
  excluded off-topic protocol prompts + excluded sessions, archival rule:
  byte-verbatim English, never translated (translating history falsifies it).
- Generation: collate script gains a third output; docs + asset regenerate
  from one run, never hand-edited.

## 2. About story + wiring

- Story block (~130 words, i18n-keyed like all About copy): frames the
  archive as the wallet's original build-story artifact — the complete
  working chat, "acquire bitshares-ui" (2026-09-26) through the issue-1 fix
  (2026-10-03), preserved unedited. Foregrounds the load-bearing decisions
  the dialog records: refusing another React uplift (#3583 → zero-dependency
  anti-rot doctrine), local-keystore signing like the old wallet (not
  outsourced like astro-ui/Beet), three themes with the classic look default,
  human-terms numbers, phone-first from slice one, fee truth from
  `get_required_fees`. Origin-story tone, no hedging.
- Wiring: new "Making of this wallet" section in the existing `/about`
  route via `about-ui.js`. Order: story block, then collapsed "Full build
  dialog (413 exchanges)" container, then a no-JS fallback line. Missing
  data file renders an "archive unavailable" line, never a blank.
- Out of scope: router, menu, themes, and locales untouched except the
  story block's keys.

## 3. Rendering rules

- Lazy-load: collapsed by default; data injected on first expansion only.
- Collapse: one native `<details>` per exchange under day-group headers,
  all collapsed by default. No JS state machine; keyboard/tap friendly.
- Search: one filter box, plain substring match over user+reply text,
  day headers show match counts, clear button restores. No fuzzy logic.
- Anchors: each exchange addressable via an `#N`-derived anchor matching
  docs numbering (exact fragment scheme at plan time — must survive the
  hash router without misrouting, e.g. must not parse as a new route);
  anchor visits auto-load data, expand the exchange, scroll to it.
- i18n: only search placeholder/clear get keys; dialog content stays
  verbatim English (see archival rule §1).
- Verification: 360px phone (scroll, ≥44px targets, no hover-only UI),
  1440px desktop (day index uses width), all three themes,
  `prefers-reduced-motion` respected (no expand animation).

## Anti-rot answers (§4.5)

- (a) Static data file + `<details>` + substring filter run in any browser,
  no services involved.
- (b) Zero new dependencies, services, toolchain, or hosted assets; the
  asset ships in the folder (`curl`-complete).
- (c) Smallest deletable subset: the data file (story + section remain,
  archive line reports unavailable) — weight is opt-in per click.
