**Recorded ambiguities (NOT guessed — testnet decides, Task 4):**
- (A) sha1/hash160: #4 defines 4 variant slots; #2 serializes only 3 (`bytes(20),bytes(20),bytes(32)` — no hash160); #1 throws on sha1. Vanilla offers sha256 + ripemd160 only and serializes variant ids 0/2; sha1/hash160 are unsupported-by-design, recorded — NOT attempted on testnet.
- (B) Preimage byte-length vs char-length: `preimage_size` = UTF-8 BYTE length (TextEncoder), not JS string length — ASCII fixtures hide the difference; the parity note records a non-ASCII preimage vector (e.g. 2-byte char → size counts bytes) or records it as untested-if-untestable.
- (C) `htlc_create.extensions` memo (`additional_options_type`, Reference #2): #1 sends none, #3 sends empty varint. Vanilla sends empty extensions; memo-in-HTLC is deferred with reason (claim-memo already covers the messaging need).
- (D) Op-26 field-order trap (Reference #7): byte-vector asserts `period_start_time` before `periods_until_expiration`; testnet update broadcast is the proof. If the node rejects, the vector (not the header) is what gets re-checked first.
- (E) Refund provability: op 53 is virtual and CANNOT be broadcast — "create→refund" means: create with SHORT `claim_period_seconds`, wait for expiry, observe (i) `get_htlc(id)` → empty/deleted, (ii) balance returned to `from`, (iii) virtual-53 row in account history if the history api exposes it. If testnet enforces a minimum claim period above the fixture value, the observed minimum is recorded and the wait is honored (no faking).
- (F) Chain `max_preimage_size` / `max_timeout_secs`: read live from `get_global_properties` in Task 2 probe; client-side caps mirror OBSERVED values only; a testnet rejection outside them is recorded, never silently clamped.
- (G) Spotlight recurring honesty: no background daemon exists in a static page — the helper places N orders NOW (one tx per order, slice-6 pattern); "recurring" scheduling beyond that is documented as out-of-scope, not implied.

**Percent/math note (principle #6):** No percent fields in this slice — but THREE human conversions are load-bearing: (1) amounts via `Format.formatAmount(raw, precision)` / `parseAmount` (never float); (2) timelocks: `claim_period_seconds` / `seconds_to_add` / `withdrawal_period_sec` render as human durations (`86400` → `1 day`, `3600` → `1 hour`) AND raw seconds stay visible in confirm rows (both, never raw-only); (3) HTLC `time_lock.expiration` + permission `period_start_time`/`expiration` render as locale date-time via `Intl` (never raw epoch). Preimage-hash renders as `<algo-name> — <hex>` (algo name from variant id 0→`ripemd160`, 2→`sha256`; NEVER the bare int). Every displayed number gets a raw→human vector in the parity note.

### Task 1: HTLC + withdraw serializers in `tx.js` (append only)

**Files:**

**Spec (from References #2–#4, #10–#12, #22–#23 — port the bytes, not the files):**
