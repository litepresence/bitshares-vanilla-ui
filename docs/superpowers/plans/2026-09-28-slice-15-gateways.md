**Goal:** Deposit/withdraw parity with #1's `AccountDepositWithdraw.jsx` gateway tabs + `XbtsxGateway.jsx` / `XbtsxGatewayDepositRequest.jsx` / `XbtsxWithdrawModal.jsx` + `GdexGateway.jsx` / `GdexGatewayInfo.jsx` + `gatewayMethods.js` / `XbtsxMethods.js` / `gdexMethods.js` / `gateways.js` / `apiConfig.js` gateway API tables + the generic `WithdrawModal.jsx` plain-transfer withdraw path, rebuilt as a gateway desk at the LIVE route `#/deposit-withdraw` (currently a `router.js:96` placeholder). FOUR adapters land: XBTSX, IOB, GDEX, BIT20 — the binding USER SCOPE (2026-09-28, SLICES.md §15). ALL other historic partners (RuDEX/Citadel/BlockTrades/Bitspark/OpenLedger/CryptoBridge/PirateCash — #1 already hard-disables them with `isEnabled: () => false` plus "Shutdown" landings, Reference #2) are OUT OF BUSINESS → OUT OF SCOPE, do NOT port. This slice is READS-ONLY plus prefilled-transfer withdraws: deposit = off-chain HTTP fetch of a deposit address/account+memo (zero chain surface, zero serializers); withdraw = the existing slice-4 op-0 transfer form PREFILLED to the gateway issuer/intermediate account with the gateway memo prefix (no new serializers — `tx.js` untouched). Every panel degrades to an honest "unavailable — <reason>" with Retry; the app works FULLY with all four gateways down (adapters are NEVER load-bearing). Liveness was probed live during planning (table below): XBTSX + IOB coin lists answer HTTP 200; BOTH GDEX API hosts time out from sandbox (000) so GDEX ships manual-only/unavailable-first; BIT20 has ZERO references in #1/#2/#3 and no resolvable host so it ships as an explicitly-disabled stub pending on-chain discovery (ambiguity B).

**Architecture:** `gateway.js` owns the adapter registry + all four per-gateway adapters + deposit-address HTTP fetchers + health cache + localStorage address cache (no DOM). `gateway-ui.js` owns the `#/deposit-withdraw` desk (gateway tabs, deposit panels, withdraw-prefill panels, unavailable panels, confirms-by-delegation). (A `gateway-extra.js` splits OUT only if `gateway.js` breaches ~380 lines; a `gateway-panels.js` splits OUT only if `gateway-ui.js` breaches ~380 lines — both pre-authorized below, no new plan needed.) `tx.js` is UNTOUCHED (no new op — withdraws reuse the slice-4 op-0 builder verbatim); `transfer-ui.js` is REUSED by delegation for withdraw confirms (prefilled form, never a forked confirm); `router.js` swaps the `#/deposit-withdraw` placeholder for the real renderer; `index.html` gains two `<script>` tags. All gateway HTTP goes through `fetch` with timeout + `AbortController`; all chain reads (issuer-account resolve, `get_required_fees` for withdraws) go through the single `Chain` module. QR is OMITTED: #1 renders QR via the npm `qrcode.react` component (Reference #8) and no zero-dep QR implementation exists on disk in `vanilla/` — deposit panels show copyable address/account+memo text instead, with the omission recorded honestly.

**Tech Stack:** Vanilla JS + `fetch` (platform) + existing `Tx`/`TransferUI`/`Chain`/`Format` modules. Node 20 stdlib for checks. Python 3 for rot gate. No new files beyond `gateway.js` + `gateway-ui.js` (+ parity note, + splits ONLY on cap breach); `router.js` + `index.html` are modified only.

### Task 1: `gateway.js` — adapter registry + health + deposit fetchers + cache (one purpose: gateway I/O, no DOM)

**Files:**
- Create: `vanilla/js/gateway.js` (global `Gateway`, `module.exports` guard, §3.7 header). (Split `gateway-extra.js` LATER only on cap breach — this file never takes DOM.)

**Interface (all return plain JSON, throw named errors `unknown-gateway` / `gateway-down` / `gateway-rejected` / `bad-account` / `bad-coin` / `disabled` / `unproven`):**
- `Gateway.list()` → `[{id: "XBTSX"|"IOB"|"GDEX"|"BIT20", name, landing, wallet, enabled, healthCachedAt}]` (static registry + live health flags; BIT20 + GDEX boot `enabled: false` with reasons — ambiguities B/D decide otherwise ONLY on live proof).
- `Gateway.health(id, {force?})` → `{ok, ms, status?, reason?, at}` — one `fetch` with 10s `AbortController` timeout per adapter (XBTSX: `GET {BASE}/coin`; IOB: `GET {BASE}/coins`; GDEX: `POST {BASE}/gateway/asset/assetList` envelope-minimal then `GET {gdex2}/coins` fallback; BIT20: immediate `{ok: false, reason: "disabled"}` — never fetched until ambiguity B resolves). Results cached `{id: {…, at}}`; stale >15 min re-probes on next call with `force` available to views' Retry buttons.
- `Gateway.coins(id)` → normalized rows `{symbol, backingCoin, depositAllowed, withdrawalAllowed, precision, issuer, issuerId, gatewayWallet?, minAmountRaw, withdrawFeeRaw, gateFeeRaw, memoSupport?}` (raw ints stay raw — formatting is the VIEW's job via `Format`). Source: live list endpoint per adapter; GDEX/BIT20 throw `disabled` while disabled.
- `Gateway.depositAddress(id, {coin, account})` → `{address, memoOrNull, cached}` — XBTSX `POST {BASE}/wallets/{walletType}/new-deposit-address` (Reference #4; GET-fallback per ambiguity A); IOB `POST {BASE}/simple-api/initiate-trade` (Reference #6); GDEX `POST {BASE}/gateway/address/getAddress` envelope (Reference #7 — reachable ONLY if Task-3 re-probe enables it); BIT20 throws `disabled`. Empty account → `bad-account` BEFORE any fetch.
