# Slice 16 (Notifications + Alerts) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Toast + alert parity with #1's `NotificationStore.js` / `NotificationActions.js` + `App.jsx` notification pump + `PriceAlert.jsx` rule modal + `PriceAlertNotifications.jsx` trigger engine + `Notifier.jsx` fill-order toasts + `BrowserNotifications.jsx` transfer-to-me browser notifications + `SettingsEntry.jsx` notification toggles, rebuilt as a zero-dependency notification center at the NEW route `#/alerts` (no such route exists in #1 — price alerts live only in the Exchange modal; the standalone view is a deliberate, recorded deviation that gives phone users and non-Exchange flows a home for rules). TWO files land: `notify.js` (toast queue + rule store + trigger engine + Web-Notification gate) + `notify-ui.js` (`#/alerts` rule CRUD + toast-stack host + permission prompt). This slice is READS-ONLY: alert checks run on the existing market ticker refresh and account-history reads (zero new sockets, zero new WS methods beyond what slices 3/5 already call); NOTHING here signs or broadcasts (no serializers — `tx.js` untouched). #1's toast libs (`react-notification-system` for DOM toasts, `notifyjs` for browser notifications — References #2/#7) are REPLACED with native DOM + the platform `Notification` API and are never ported. Durations are ported verbatim (10s default / 30s price-alert / 5s fill — Reference #12). Fulfilled price rules SELF-DELETE after firing (port of `PriceAlertNotifications.jsx:173-179` semantics). Web Notifications ship default-OFF behind an explicit user toggle with an honest unsupported fallback — a deliberate deviation from #1's default-allow + mount-time auto-request (ambiguity D).

**Architecture:** `notify.js` owns the toast queue + alert-rule CRUD + decimal-exact trigger engine + activity watcher + preference flags + `localStorage` persistence (no DOM except the platform `Notification` constructor). `notify-ui.js` owns the `#/alerts` view (rule list grouped by pair, add/edit/delete form, toast-stack renderer, permission section) plus the market-desk bell entry point. (A `notify-extra.js` splits OUT only if `notify.js` breaches ~380 lines; a `notify-panels.js` splits OUT only if `notify-ui.js` breaches ~380 lines — both pre-authorized below, no new plan needed.) The trigger engine is PULLED, never pushed: `market-ui.js`'s existing 15s ticker refresh calls `Notify.checkAlerts(pairKey, humanPrice)` after it already has the ticker (Reference #11); account views call `Notify.checkHistory(prevFirst, rows)` after their existing history fetch (Reference #13). `tx.js` is UNTOUCHED; `transfer-ui.js` / `trade-ui.js` result panels are UNTOUCHED (their inline result states stay the primary confirm UX — toasts supplement, never fork). `router.js` gains ONE route (`#/alerts`); `index.html` gains two `<script>` tags. Toast stack host is a single `<div id="toast-stack">` appended to `document.body` by `notify-ui.js` on first use (no `index.html` markup change needed); styling appends to the existing `css/app.css` (+ `themes.css` tokens only, no new palette values).

**Tech Stack:** Vanilla JS + `localStorage` (platform) + existing `Chain`/`Market`/`Account`/`Format` modules + platform `Notification` API (gated). Node 20 stdlib for checks. Python 3 for rot gate. No new files beyond `notify.js` + `notify-ui.js` (+ parity note, + splits ONLY on cap breach); `router.js` + `index.html` + `css/app.css` are modified only (surgical appends).

**Percent/math note (principle #6):** TWO human conversions are load-bearing, ZERO percent fields exist in this slice (no `GRAPHENE_100_PERCENT` math — stated so the audit doesn't hunt for it): (1) alert thresholds are HUMAN prices with BOTH precisions: the engine compares the rule's display-decimal string against the ticker's human price string with EXACT decimal comparison (scaled-integer cross-multiplication via `Format.parsePriceRatio`-shaped `{num,den}` pairs — never `Number()`, never `parseFloat`; #1 itself wraps everything in `Number()` at `PriceAlertNotifications.jsx:47-54` and that float comparison is NOT copied); vectors include one non-BTS precision pair plus the string-exactness case (`"0.1"` vs `"0.10"` equal, `"0.1000001"` greater at precision 6). ### Task 1: `notify.js` — toast queue + rule store + exact trigger engine + watcher + prefs (one purpose: notification state, no DOM except `new Notification`)

**Files:**
- Create: `vanilla/js/notify.js` (global `Notify`, `module.exports` guard, §3.7 header). (Split `notify-extra.js` LATER only on cap breach — this file never takes view DOM.)

**Interface (all return plain JSON/strings, throw named errors `bad-rule` / `bad-pair` / `unknown-asset` / `no-price`):**
- `Notify.push(level, title, body, {durationMs?, sticky?})` → `{id}` — levels `success|info|warning|error` (port of `normalize`, Reference #1); bare-string body wrapped as `{message}`; default duration 10_000ms (Reference #12); price-alert calls pass 30_000, fill calls 5_000. Queue (max 5 visible, overflow counts "+N more", never unbounded DOM). Subscribers notified; returns id for dismissal.
- `Notify.dismiss(id)` / `Notify.clear()` — tap-to-dismiss backing (views wire buttons, engine never auto-dismisses sticky errors).
- `Notify.rules()` → `[{key, quote, base, type: "1"|"2", price}]` (price = display string, verbatim like #1 — Reference #4 ambiguity B cap enforced at `addRule`, not here).
- `Notify.addRule({quote, base, type, price})` → `{key}` — validates type ∈ {"1","2"}, non-empty symbols, price matches `^\d+(\.\d+)?$` with decimals ≤ `max(basePrec, quotePrec)` (precisions passed in or resolved via `Chain` cache — builder picks per ambiguity B, records it); throws `bad-rule` otherwise.
- `Notify.removeRule(key)` / `Notify.rulesFor(quote, base)` (pair filter — port of `getPriceAlertRules`, Reference #5) / `Notify.hasAny(quote, base)` (bell indicator — port of `hasAnyPriceAlert`, Reference #9).
- `Notify.compare(humanA, humanB)` → `-1|0|1` — EXACT decimal compare via scaled BigInt (fraction parts right-padded to common length, compared as BigInt; integer part compared by length-then-lex). Never `Number()`. This is the ONLY price comparison the engine uses.
- `Notify.checkAlerts(pairKey, humanPrice)` → `{fired: [{rule, actual}], kept: n}` — for each stored rule on `pairKey` (`QUOTE_BASE` key shape, port of Reference #7): skip when `humanPrice` is null/undefined (no-price path — never fires on missing feed); HIGHER ("1") fires at `compare(actual, expected) >= 0`, LOWER ("2") at `<= 0`; each fired rule pushes a 30s toast with the Reference-#8 WORDS ("rose higher than … and is now …" / "fell lower than …") AND is deleted (self-delete semantics, Reference #7); returns the fired list for the view/tests.
- `Notify.checkHistory(prevFirstId, rows, {watchAccounts})` → `{events: [{kind: "fill"|"transfer-to-me", row}], firstId}` — diffs newest-first history rows by id (port of References #10/#11): `fill` when row op is `fill_order` with a new id; `transfer-to-me` when row op is `transfer` with `to` in `watchAccounts` and a new id; same-id → no events (asserted in Task 3). Pushes 5s fill toasts (Reference #12) and transfer toasts gated by the `transferToMe` pref; returns new `firstId` for the caller to persist per-view (no global polling state in this module).
- `Notify.prefs()` / `Notify.setPrefs({browser?, transferToMe?})` — defaults `{browser: false, transferToMe: true}` (ambiguity D deviation, recorded); persisted `notify_prefs_v1` in `localStorage`; `browser:true` requires a prior explicit `Notify.enableBrowser()` (which is the ONLY caller of `Notification.requestPermission` — never called on load, never called implicitly).
- `Notify.notifyBrowser(title, body)` — no-op returning `{skipped: reason}` unless prefs.browser AND `window.Notification` exists AND `permission === "granted"` (honest skip reasons: `disabled|unsupported|denied|default` — views surface these, never throw).
- Persistence: rules under `notify_alerts_v1` (`{v:1, at, rules}` envelope), prefs under `notify_prefs_v1`. Stale-pair sweep per ambiguity F (unresolved-pair badge data + 7-day drop) lives here if it fits, else in the pre-authorized split.

- [ ] **Step 1: Implement** (~380 lines max; watcher + prefs + sweep overrun splits `notify-extra.js`, never a second concern in this file). Rule `type` stays STRING "1"/"2" (Reference #3 — strict `===` against `"1"`/`"2"` only, never truthy checks).
- [ ] **Step 2: Syntax + offline vectors** — `node --check js/notify.js`, exit 0; headless `node` run (no network): `compare` vectors (`"0.1"` vs `"0.10"` → 0; `"0.1000001"` vs `"0.10"` → 1 at p6; long-decimal exactness; integer-length shortcut); `checkAlerts` fixture (HIGHER fires at equal, LOWER fires at equal, NaN/null price never fires, fired rules deleted, kept count right); `checkHistory` fixture (fill-only row fires fill, transfer-to-me fires gated, same-id silent, unknown op silent); `addRule` rejects (bad type, empty pair, over-precision decimals per ambiguity-B cap); prefs round-trip + `notifyBrowser` skipped-reasons without a DOM.

**Acceptance:** `node --check` green; all offline vectors pass with EXACT decimal semantics (zero `Number()`/`parseFloat` in the file — grep proves it); fired-rules deletion proven; missing-feed never fires; no `Chain` writes, no `Tx` reference, no `Notification.requestPermission` outside `enableBrowser`.
