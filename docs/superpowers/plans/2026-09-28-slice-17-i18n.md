**Architecture:** `i18n.js` owns dict registry + `t(key, enDefault)` + fallback chain + `%(name)s` interpolation + `I18n.date()`/`I18n.num()` `Intl` wrappers + `{v:1}`-enveloped `localStorage` dict cache + locale pref read/write through the existing `Store` settings envelope (no DOM except toast-free silent fallback — a missing dict never throws past the caller). `locales/*.json` are DATA (line caps do not apply to JSON; `_meta.untranslated` marks stubs). `settings.js` owns the ONLY new UI: a locale `<select>` mirroring the theme selector (Reference #10) with stub entries suffixed `" — in English"` (honest marking) plus an offline-failure toast path. No per-component dicts (#2's namespaced pattern is REJECTED — vanilla views are plain scripts with no component scope to key off; one global dict per locale, #1-style sections, decision recorded per Reference #9).

**Tech Stack:** Vanilla JS + `fetch` (locale JSON over http, #1's own web path — Reference #3) + `localStorage` dict cache + platform `Intl.DateTimeFormat`/`Intl.NumberFormat` (no ICU dep, no `react-intl`, no `counterpart`). Node 20 stdlib for checks. Python 3 for rot gate + drift check. No new files beyond `i18n.js` + `locales/*.json` (+ parity note); `settings.js` + `index.html` + `htlc.js` are modified only (surgical).
