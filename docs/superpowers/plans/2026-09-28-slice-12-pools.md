# Slice 12 (Pools + Swap + Stake) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Liquidity-pool parity with #1's Poolmart list + exchange/stake modals and #2's pool/swap/stake pages, rebuilt as a pools desk that mirrors the orderbook desk per the user's DEX-UX direction (same design language, seamless feel): pool list + pool detail over `1.19.x` objects at live routes `#/pools` + `#/pools/:id`, a simple single-pool swap page at `#/swap` (new route — `#/instant-trade` stays a placeholder, see scope decision), and stake/unstake views that ARE `liquidity_pool_deposit`/`withdraw` (NOT ticket staking — slice 14 owns ops 57/58). SIX signing ops land: create (op 59) / delete (op 60, fee 0) / deposit (op 61) / withdraw (op 62) / exchange (op 63) / update (op 75, fee edit only). Every chain op is a SIGNING op: human-readable confirm dialog with NAMED rows (percent fields as `x%`, never raw u16; amounts human; pool id + both assets named — beats #3's bare-id rows, References #24–25) + live `get_required_fees` (never static tables, per #3720) + testnet broadcast round-trips with on-chain re-read proof, following the slice-8/10/11 pattern (`Tx.fee`/`buildTx`/`sign`/broadcast + re-read proof; `vote-ui.js` `sendAndProve` precedent, Reference #27). Pool exchange executes immediately against the pool (CPMM `x*y=k`) — it is NOT an orderbook fill: no limit-order book, no fill-or-kill, result is `generic_exchange_operation_result` carrying 3 fees (maker market fee, taker market fee, pool taker fee, Reference #6). Candles come from CHAIN pool history only — the DEX-UX Elasticsearch flow is documented below as the anti-pattern we deliberately do NOT copy (no ES URL, no ES fetch, ever).

**Architecture:** `pool.js` owns ALL pool chain reads + op-data builders + pool math (CPMM quote, share-price, depth points — no DOM). `pool-ui.js` owns the pools desk (list + detail + stake/unstake + exchange panels) + confirm dialogs. (`pool-swap-ui.js` splits OUT only if either file breaches ~380 lines — pre-authorized below, no new plan needed.) `tx.js` grows SIX serializers append-only (ops 59, 60, 61, 62, 63, 75), following the slice-8/10/11 precedent (append, never fork). `router.js` swaps the `#/pools` stub for the real renderer and adds `#/pools/:id` + `#/swap`; `index.html` gains two `<script>` tags (three if the swap split triggers). No crypto change (no hashing, no memos in pool ops), no new socket code — all chain I/O through the single `Chain` module (`Chain.db` for pool reads, `Chain.history()` for pool history — VERIFY it lives there, ambiguity C).

**Tech Stack:** Vanilla JS + `Chain.db/call` reads + `Chain.history()` pool history + existing `Tx.fee`/`buildTx`/`sign`/broadcast + `Format` string math (`formatAmount`/`parseAmount` + percent helpers). Node 20 stdlib for checks. Python 3 for rot gate. No new files beyond `pool.js` + `pool-ui.js` (+ parity note, + `pool-swap-ui.js` ONLY on cap breach); `tx.js` + `index.html` + `router.js` are modified only.
