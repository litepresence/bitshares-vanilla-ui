# Slice 10 (Asset Ops) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Asset-ops parity with the old UI's UIA/smartcoin flows plus the astro-ui long tail at new vanilla routes under `#/assets/*`: UIA create (op 10, no bitasset_opts) / smartcoin create (op 10, with bitasset_opts) / NFT-metadata create (same op 10 with `nft_object` description JSON — see scope decision) / PMA create (op 10 with `is_prediction_market:true` — see scope decision), asset update (op 11), bitasset options update (op 12), feed-producer set update (op 13), issue to account (op 14), reserve/burn-back (op 15), and feed publishing (op 19) for MPA issuers/feed producers. Every op is a SIGNING op: human-readable confirm dialog with NAMED rows (never raw JSON — beats #3's `JSON.stringify` rows, References #31–33) + live `get_required_fees` (never static tables, per #3720) + testnet broadcast round-trip with on-chain re-read proof, following the slice-8 vote pattern (local send + on-chain re-read; `vanilla/js/tx.js` fee/build/sign/broadcast + `vanilla/js/vote-ui.js` `sendAndProve` precedent, References #34–35). Read-only asset inspection stays owned by slice 9 (`#/asset/:symbol`, `Explorer.asset`); this slice OWNS the fee-schedule Fees display deferred from slice 9 (Reference #20).

**Architecture:** `asset.js` owns ALL asset-op chain reads + op-data builders (no DOM). `asset-ui.js` owns the create/update/issue/reserve views + confirm dialogs. `asset-feed-ui.js` owns the feed-publish + feed-producer views (split upfront per the slice-9 ~400-line lesson — three files, one purpose each, each ≤380 lines). `tx.js` grows SIX serializers append-only (ops 10, 11, 12, 13, 14, 15, 19 — see Task 1 for the exact list and the op-16 deferral), following the slice-8 precedent (append, never fork). `router.js` swaps/extends stubs for the new `#/assets/*` routes; `index.html` gains three `<script>` tags. No crypto change, no new socket code — all chain I/O through the single `Chain` module.

**Tech Stack:** Vanilla JS + `Chain.db/call` reads + existing `Tx.fee`/`feeMulti`/`buildTx`/`sign`/broadcast + `Format` string math (`formatAmount`/`parseAmount`/`formatPrice`). Node 20 stdlib for checks. Python 3 for rot gate. No new files beyond `asset.js` + `asset-ui.js` + `asset-feed-ui.js` (+ parity note); `tx.js` + `index.html` + `router.js` are modified only.
